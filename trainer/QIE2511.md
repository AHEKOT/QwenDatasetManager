# QIE2511: совместное обучение edit и RGB/RGBA

В форме выберите **Qwen Image Edit 2511 — Edit RGB / RGBA LoRA**.
Для новых датасетов выбран **Paired edit · RGB / RGBA**:

- `Control1/name.jpg` — реальный вход; `Control2` и `Control3` — дополнительные входы, если нужны.
- `img/name.png` (или JPEG/WebP) — ожидаемый результат редактирования.
- `img/name.txt` — инструкция изменения. Расширение каптиона и общий default caption настраиваются в форме.

Имена без расширения должны совпадать. Каждый используемый Control должен
содержать пару для каждой цели. Сервис проверяет это при сохранении и запуске.

Можно использовать полностью RGB-датасет, полностью RGBA или смешанный.
RGB получает непрозрачную альфу 1, RGBA сохраняет свою альфу, включая частичную
прозрачность. Наличие прозрачных пикселей не обязательно. Цвета непрозрачных
изображений не меняются обработкой краёв альфы. Исходные файлы не изменяются.

Backend использует совместимый обученный RGBA VAE (по умолчанию
`models/vae/QIE2511-rgba.safetensors`). Обычный RGB VAE не умеет кодировать альфу.
Обычный вариант QIE с RGB VAE остаётся доступен отдельно для прежних заданий.

Обучается **полный latent diffusion loss**: и содержимое/цвет изображения,
и его альфа. Alpha-only фильтрация в QIE отключена во всех режимах. Если через
Advanced задан `model.model_kwargs.rgba_lora_alpha_probe_path`, совместимый
калиброванный probe добавляет вспомогательный loss альфы/краёв. Без probe
QIE обучается полным loss, а не скрытым alpha-only loss; дополнительного
декодирования VAE на каждом шаге для этого не требуется.

Парный режим использует реальные Control, без фонового датасета и синтетической
подстановки входа. Caption dropout и кэширование текста сохраняют обычные
настройки; лимит QIE на `unload_text_encoder` остаётся прежним.
При кэшировании латентов пиксели цели доступны для RGBA-метрик и дополнительных
loss, если они включены. Старые сохранённые `edit` и `generation` режимы не
переключаются автоматически: `edit` теперь подписан как **Automatic background
removal**, а `generation` использует пустой вход.

Для независимой валидации выберите **Paired edit · RGB / RGBA**, загрузите
RGB/RGBA-результат, входные Control и введите инструкцию. Входы используются
и текстовым энкодером, и transformer conditioning. Полный validation loss
измеряет отклонение от результата, alpha-метрики выводятся отдельно. Alpha
PASS/FAIL сам по себе не оценивает выполнение инструкции; это также проверяется
по периодическим сэмплам с реальными входами.

Проверено тестами: RGB/RGBA/mixed конфиги и очередь, отсутствующие пары,
загрузка обычной RGB-валидации, реальные входные Control, подготовка пикселей,
полный RGB-градиент при правильной альфе, кэш валидации с несколькими входами.
Полноразмерное GPU-обучение в рамках этой проверки не запускалось.
