# MiniMax H3 в QDM

Перенос выполнен из `D:\AiToolkitNew\AI-Toolkit`, commit
`3e1cb5f67f7bebe6ac74e3da5105d18fb3c1dd5a`. Реестр включает обычную H3
и Ref2VA, их прозрачные варианты и общий тренер RGBA VAE.

## Локальные модели

Корень по умолчанию — `E:\Development\QwenDatasetManager\models` для этой
установки. Он вычисляется относительно проекта и используется также при
прямом запуске vendored runtime. Форма позволяет выбрать другой корень;
запуск из очереди передаёт его через `MODELS_PATH` до импорта backend.
При самостоятельном запуске YAML с другим корнем задайте `MODELS_PATH`.

Ожидаемая структура:

```text
models/
  diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors
  diffusion_models/minimax_h3_ref2va_pruned_int8_convrot.safetensors
  text_encoders/qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors
  vae/minimax_h3_video_vae_fp16.safetensors
  vae/minimax_h3_audio_vae_fp32.safetensors
  loras/training_adapters/minimax_h3_training_adapter_v2.safetensors
  loras/training_adapters/minimax_h3_ref2va_training_adapter_v1.safetensors
```

На момент переноса всё перечисленное, кроме **FL2VA transformer**, находится
в папке проекта. Обычных FL2VA-весов нет и в исходной установке. При разрешённой
сети отсутствующий компонент скачивается из исходного репозитория в этот
корень; `Local files only` вместо скачивания сообщает, какой файл отсутствует.
Ref2VA никогда не подставляется вместо FL2VA.

Отдельно задаются transformer, text encoder, video/audio VAE и папка
tokenizer/processor/text_encoder config. Полностью автономный режим требует
также этих небольших файлов исходного `MiniMaxAI/MiniMax-H3` или заполненного
HF cache. Наличие только safetensors не заменяет tokenizer/config.
Локальный обычный адаптер v2 выбирается автоматически; явный путь пользователя
имеет приоритет. Для Ref2VA используется её собственный адаптер v1.

## Что перенесено

| Область | Поддержка |
|---|---|
| Архитектуры | FL2VA и Ref2VA, полные и pruned partitions, отдельные пути компонентов |
| Загрузка | Comfy single-file layout, вложенные локальные папки, offline, ConvRot8 DiT, NVFP4/AWQ Qwen3-VL, смена quantization, layer offload |
| De-turbo | CG, Training Adapter, оба, None; Ref2VA также D-OPSD и bleed strength |
| Адаптер | Frozen live adapter при обучении; отключён при sampling, не сливается с quantized base |
| Датасеты | Картинки и видео в `img`, необязательные Control1–3, captions, повторы, веса, кеши, flips, resolutions |
| Видео и звук | `17n+5` кадров, single-frame mode, auto frame count, FPS, fit/trim, audio loss, normalize, preserve pitch, совместный audio/video DTO и cache |
| Conditioning | First-frame I2V обычной H3; image/video refs Ref2VA; still refs as video, количество кадров reference, token limit |
| D-OPSD | Teacher self-reference, отдельные student/teacher caption caches, pixel cache, teacher target и bleed loss, без внешних controls/CG/adapter |
| Sampling | Prompt-only, image/video refs, длина, 24 FPS, звук, seed, размеры, CFG/steps, gallery, control preview, download/ZIP |
| Общий тренер | LoRA/LoKr, optimizer, accumulation, timestep shift, EMA, preservation, save/resume, queue/stop/save/sample, Advanced JSON |

Скопирован весь каталог H3 (13 Python-файлов), включая packing, pipeline,
оба VAE, Qwen3-VL presentation, reference video cache и вспомогательные VSA
модули. FastH3 сохранён в исходном модуле, но отдельно не зарегистрирован:
запрос касается обычной H3 и Ref2VA.

При создании текстового кэша H3 размер визуальных референсов ограничен
максимальным разрешением, выбранным **для этого датасета**: `[256, 512]`
даёт предел 512 по длинной стороне. Изображения уменьшаются на CPU до
создания тензоров, кадры видео — до передачи vision processor. Размеры
выравниваются вниз на сетку Qwen3-VL (32 пикселя); маленькие изображения
не увеличиваются, кроме необходимого минимума в один блок. Автоматическое
увеличение processor отключается. Это относится также к image-as-video,
I2V и teacher conditioning D-OPSD. Максимум сохраняется при разбиении
multi-resolution датасета и входит в ключ кэша: после смены разрешения
визуальные embeddings пересчитываются. Исходные файлы не изменяются.

Перенесены зависимые DTO, v2 loader/resolver/text encoder, quantization и
memory-management изменения. В SDTrainer и dataloader объединены только
нужные H3 изменения с существующим RGBA-кодом. Локальная обработка alpha,
sampling LoRA и поведение накопления градиентов сохранены.

## Обучение прозрачного VAE

1. Выберите **MiniMax H3 / Ref2VA — Train RGBA VAE**.
2. Исходный VAE — локальный RGB `models/vae/minimax_h3_video_vae_fp16.safetensors`.
3. Добавьте датасеты PNG/WebP с настоящим alpha; нужно минимум две картинки.
   Captions и Control-папки для VAE не используются. Размер кратен 32.
4. Выберите Full VAE или Alpha boundary only. Доступны FP32 master weights,
   compute dtype, gradient checkpointing, alpha LR multiplier, reconstruction,
   alpha/edge/composite/opaque-latent losses и критерии READY.
5. Оцените holdout и previews. READY означает прохождение заданных порогов,
   а не подтверждённое качество последующего diffusion/video generation.

Расширяются только вход encoder с RGB до RGBA и выходная patch projection
decoder с 3072 до 4096 строк. Последние 1024 строки соответствуют alpha;
исходные 24 latent channels, temporal geometry и latent statistics сохранены.
Начальное расширение воспроизводит прежние RGB latents/reconstruction с
непрозрачной alpha. Эталонный encoder заморожен и имеет независимые веса.

Checkpoint: `trainer/output/<job>/<job>_step_<step>_h3/` содержит
`minimax_h3_rgba_vae.safetensors`, optimizer/step state, readiness и, при
включённом экспорте, `*_ComfyUI_bf16.safetensors`. Повторный запуск задания
возобновляет последний checkpoint. «Sample now» выполняет validation.

Обученные веса можно выбрать по полному пути в LoRA-тренере либо скопировать
в `models/vae/minimax_h3_rgba_vae.safetensors`. Этот файл **не создаётся как
фиктивная обученная модель при установке** — сначала требуется обучение VAE.

## Прозрачные LoRA

Выберите обычную H3 или Ref2VA с пометкой **Transparent RGBA LoRA** и укажите
обученный H3 RGBA VAE. Файлы Qwen/FLUX/RGB H3 отвергаются runtime до загрузки
DiT. Кеши RGBA отделены от RGB и учитывают версию VAE.

Текущие прозрачные датасеты — **single-frame RGBA изображения**, как у других
локальных прозрачных тренеров; видеофайлы target явно отвергаются. В Edit
target композится с выбранным случайным непрозрачным фоном: обычная H3 получает
first-frame condition, Ref2VA — reference condition. Dynamic edit отключает
text cache и выгрузку TE. Generation обучается по caption без искусственного
чёрного reference. Обе ветки используют полный RGBA flow loss и дополнительную
дифференцируемую реконструкцию alpha/edges через VAE; это требует памяти для
decoder. Нулевые alpha/edge strengths оставляют только latent flow loss.

Сохраняются de-turbo режимы, включая D-OPSD у Ref2VA: self-reference teacher
получает RGBA latent, Qwen3-VL видит RGB, student не получает внешних controls.
В D-OPSD teacher/student embeddings и pixels кешируются обязательно.

Сэмплы могут быть картинками или видео. RGBA-видео сохраняется в lossless
animated PNG, звук — в соседний WAV. Галерея проигрывает APNG, предоставляет
audio player; ZIP и удаление учитывают WAV. Обычные RGB H3 сэмплы остаются MP4.
Качество прозрачного видео после обучения только на картинках нужно оценивать
отдельно: оно не подтверждается single-frame holdout.

## ComfyUI

Stock loader создаёт H3 VAE с RGB boundaries и трёхканальной pixel normalization
([официальный код](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy/sd.py)).
Для RGBA добавлена поддержка в существующий пакет
`ComfyUI-FLUX2-Klein-RGBA`:

- **H3 RGBA VAE Loader (QDM)** — выход стандартного типа `VAE`, отдельная
  инициализация RGBA native H3, без глобального monkeypatch;
- **H3 RGBA Encode (QDM)** — RGBA frames или RGB + стандартная Comfy mask;
- **H3 RGBA Decode (QDM)** — RGBA, RGB и mask; `mask=1` означает прозрачность.

Обновите копию пакета в `ComfyUI/custom_nodes/`, перезапустите ComfyUI,
положите checkpoint в `ComfyUI/models/vae`. Используйте loader и для reference
conditioning, и для декодирования. Decode принимает как video latent,
так и совместный H3 audio/video latent: выбирает видеопоток, не меняя звук.
Звук декодируется отдельно через обычный audio VAE. RGBA выход
сохраняйте как PNG/последовательность PNG; стандартный MP4 не хранит alpha.
Нужна версия ComfyUI с native H3. Comfy wrapper проверен на контракте API,
полный inference в установленном ComfyUI в рамках переноса не запускался.
