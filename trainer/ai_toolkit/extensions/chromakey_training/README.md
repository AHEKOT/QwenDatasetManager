# KeyMatte V4: архитектура и обучение

Переработка от 10 сентября 2026. Цель — лёгкий chromakey для изображений
персонажей: дробная альфа волос, прозрачные отверстия внутри силуэта и чистый
foreground RGB. Обучение — RTX 5070 Ti 16 GB; инференс — также CPU.

## Анализ решений

| Решение, первоисточник | Что полезно | Решение для этого проекта |
| --- | --- | --- |
| [MODNet](https://github.com/ZHKKKe/MODNet), [статья](https://arxiv.org/abs/2011.11961) | Разделение семантики, деталей и объединения; компактная CNN | Используем принцип разделения задач. Портретная alpha-модель сама по себе не восстанавливает чистый RGB персонажа. |
| [Background Matting V2](https://github.com/PeterL1n/BackgroundMattingV2) | Низкое разрешение для контекста, детализация высокого разрешения; alpha и foreground | Используем общую схему context/refinement. Оригиналу нужен отдельный кадр фона; здесь его нет. |
| [FBA Matting](https://github.com/MarcoForte/FBA_Matting) | Совместное обучение foreground/background/alpha, композиционные и многомасштабные потери | Используем прямую супервизию цвета и альфы. Оригинальный trimap workflow и размер модели не подходят для дешёвого автоматического инференса. |
| [Robust Video Matting](https://github.com/PeterL1n/RobustVideoMatting) | Рекуррентная память, foreground RGB, быстрый video matting | Для последовательного видео разумный кандидат. Текущий проект обрабатывает независимые изображения персонажей; временная память здесь не нужна. |
| [ViTMatte](https://github.com/hustvl/ViTMatte) | Предобученный ViT и detail capture для маттинга | Не выбираем тяжёлый backbone и trimap-зависимость для основной модели. |
| [BiRefNet](https://github.com/ZhengPeng7/BiRefNet), [matting weights](https://huggingface.co/ZhengPeng7/BiRefNet-matting) | Общий foreground extraction, high-resolution matting | Полезный внешний baseline для маски. Не решает автоматически наш контракт чистого RGB/despill; компактная специализированная CNN предпочтительнее по вычислениям. |
| [Color-aware Deep Temporal Backdrop Duplex Matting](https://arxiv.org/abs/2306.02954) | Явно рассматривает foreground colour и spill compensation | Подтверждает необходимость оценивать цвет отдельно от alpha. Требует двух кадров с разными фонами, поэтому напрямую неприменим. |

V4 — оригинальная реализация этих общих принципов, а не копия перечисленных
моделей или использование их обученных весов. Качество опубликованных моделей
и их FPS нельзя переносить на V4 без измерений.

## Что мешало V3

- RGB исправлялся ограниченной поправкой ±0,25 и вычитанием screen chroma.
  Для пикселя, почти полностью смешанного с экраном, этого недостаточно:
  нужно оценивать цвет волоса, а не только подавлять зелёный канал.
- Premultiplied RGB ресайзился в 8 битах. При alpha=2/255 цвет после деления
  получается грубо квантованным. V4 умножает и ресайзит в float32.
- Border key и семантика каждого тайла зависели от локального кадрирования.
  V4 получает контекст целого изображения даже при обучении на маленьком crop.
- Нормализация по пространству в локальной ветке меняет ответ при смене тайла.
  В V4 GroupNorm есть только в глобальной сети, локальная ветка без нормализации.
- Spill добавлялся к уже скомпозированному изображению. Теперь отражённый свет
  портит foreground до alpha-compositing; смешение с экраном моделируется отдельно.
- Preview без GT не позволяет выбрать лучшую модель. Теперь есть фиксированный
  source holdout и численные метрики, включая цвет, тонкие структуры и отверстия.

Выборочная проверка данных: seed 42, по 12 PNG/WebP из `img/`. В `ChromaKeyX`
(455 файлов) fractional alpha занимала 0,87–1,62% пикселей выбранных изображений;
в `ChromaKeyX_New` (638 файлов) — 0,07–0,64%. Это не полная оценка качества
разметки, но показывает, почему границы нельзя усреднять вместе со всем фоном.

## Архитектура: 539 519 параметров

`ComfyUI-QDM-ChromaKey/qdm_chromakey_core/v4.py`, ID `qdm_keymatte_v4`.

1. Глобальная CNN получает RGB 256×256. Это только представление контекста;
   вход и выход локальной ветки сохраняют геометрию и пиксели оригинала.
   Encoder: 24/40/64/96/128 каналов, depthwise residual blocks, GroupNorm.
   Decoder выдаёт 16 признаков и coarse alpha logits на сетке 64×64.
2. Обучаемая attention по всему кадру оценивает цвет экрана. Это дополнительный
   признак, а не маска, жёсткий порог или добавка к конечной альфе.
3. Узкая 24-канальная локальная CNN с depthwise convolutions получает исходный
   RGB, контекст, цвет экрана и RGB−key. Dilation 1/2/4/1, без spatial norm.
4. Alpha-head исправляет coarse logits без ограничения амплитуды.
   Foreground-head предсказывает RGB residual в диапазоне ±1, независимо от
   alpha и spill-head. Обучение использует unclipped RGB, чтобы не терять
   градиент на насыщенных каналах; для экспорта RGB ограничивается [0,1].
5. Вспомогательная spill-head обучается отдельно и не ограничивает коррекцию
   цвета. На тонких волосах модель может сохранить дробную alpha и восстановить
   RGB даже при отсутствии отдельно добавленного отражённого spill.

Инференс: глобальная сеть запускается один раз. Тайлы по 512 px получают halo
12 px и одну глобальную систему координат. Сохраняется только центральная часть
тайла; усреднения straight RGB на швах нет. Координаты вычисляются в FP32,
поскольку FP16 недостаточно для индивидуальных пикселей в 4K. Ни заполнения
отверстий, ни эрозии финальной маски, ни пороговой бинаризации нет.

## Настройка обучения

Новая задача в GUI: **QDM KeyMatte V4**. Старые V1–V3 optimizer/weights не
совместимы; существующая старая задача выдаёт понятную ошибку вместо молчаливого
продолжения другой архитектурой. Старые файлы остаются доступны для инференса.

| Параметр | Начальная настройка |
| --- | --- |
| Optimizer | AdamW, LR 3e-4, weight decay 1e-4, gradient norm 1 |
| Steps | 50 000; это бюджет, качество определяется holdout, а не количеством шагов |
| LR | 1000 шагов warmup, затем cosine до 5% исходного LR; warmup ≤10% короткого запуска |
| Precision | BF16 на 5070 Ti; FP16 с GradScaler или FP32 доступны |
| Microbatch | До 8 изображений, бюджет 2 MP; минимум одно изображение |
| Accumulation | 2; эффективное число изображений зависит от aspect bucket |
| Resolutions | Площади 384² / 512² / 768², max long side 1280 |
| Native source cap | 4096 px; более крупные источники уменьшаются для ограничения CPU RAM |
| Workers | 0 на Windows как начальная настройка |
| EMA | 0,995 с прогревом decay |
| Save / validation | Каждые 500 / 250 optimizer steps |

В начале (0–10% бюджета) — целые изображения, облегчённые загрязнения экрана.
После 10% включаются native crops с вероятностью 70%; sampler выбирает края и
внутренние отверстия. Сила загрязнений растёт до полной к 30% бюджета. Остальные
30% примеров продолжают показывать целого персонажа.

Фон: green/blue/white/black = 40/30/15/15, градиенты, грязь, шум. 70% композитов
используют точную piecewise sRGB transfer function для linear-light blending,
30% — распространённую sRGB-композицию. Spill возникает на foreground до
композитинга; есть чистые контрольные примеры и естественные цвета персонажа,
близкие к экрану. Exact colour collision уменьшен до 5%: полностью совпавшие
цвета принципиально неоднозначны. JPEG 4:2:0 добавляется в 25% примеров, небольшие
synthetic hair/hole patches — в 25%. Все случайные операции зависят от seed
конкретного примера и воспроизводятся независимо от числа workers.

Основные веса: balanced alpha 1, soft BCE 0,25, hard pixels 1, edge 2,
multiscale detail 2, thin structures 2, holes 2, global semantic 0,5,
foreground RGB 1, despill RGB 2, clean identity 0,5, black/white composites 2.
Spill auxiliary 0,1, key 0,25; silhouette Dice выключен по умолчанию.
Региональные потери нормализуются отдельно и по изображениям. RGB supervise
сохраняется на fractional alpha; малые области не растворяются в площади фона.

## Проверка и артефакты

- До синтеза удаляются точные файловые дубликаты и выделяется 5% источников
  (минимум 1) в holdout. Split фиксируется в `source_split_v4.json`; смена списка
  источников при resume требует новой задачи. Отсутствующая/константная alpha
  отклоняется, а не превращается в ложный полностью непрозрачный GT.
- Быстрая валидация использует первые 8 источников holdout с фиксированными
  seed на всех четырёх семействах экранов. Это synthetic holdout; загруженные
  реальные RGB дополнительно сохраняются как визуальные previews, без выдуманных
  численных оценок там, где нет GT.
- `validation_metrics.jsonl`: alpha MAE/MSE, edge/thin/holes MAE, foreground RGB,
  despill, composite и edge composite. Это проектные метрики, не утверждение об
  официальных SAD/Gradient/Connectivity scores matting-бенчмарков.
- `_best.safetensors` выбирается по сумме alpha/edge/thin/holes/edge-composite/
  despill MAE; `best_metrics.json` хранит отдельные составляющие и случаи.
  Основной artifact указывает на best; latest сохраняется отдельно.
- Resume сохраняет optimizer, scaler, scheduler, EMA и позицию потреблённого
  batch. Prefetch не считается потреблёнными данными; незавершённое накопление
  после stop проигрывается заново. Пропущенный AMP update не двигает LR/EMA.

Варианты одного персонажа, перекодированные дубликаты и ошибки исходной альфы
автоматически не распознаются. Для итогового сравнения необходим отдельный
набор персонажей с проверенными RGBA, реальными dirty screens, волосами 1–2 px,
пустотами и screen-coloured foreground. Отсутствующие в исходной RGBA волосы
невозможно вернуть супервизией. Полное совпадение цвета волоса и экрана в одном
RGB не имеет единственного точного решения: сеть использует контекст.

## Измерения реализации

Измерено здесь, PyTorch 2.13.0+cu130, tile 512, CPU input/output, без чтения файлов,
без torch.compile/ONNX, после двух прогревов, медиана трёх запусков. Веса случайные:
это измерение вычислений, а не доказательство качества обученной модели.

| Режим | 720p | 1080p | 4K |
| --- | --- | --- | --- |
| RTX 5070 Ti, FP16 | 61 мс | 55 мс | 178 мс |
| Доступный AMD CPU, FP32, 4 threads | 616 мс | 1421 мс | не измерено |

Небольшой замер 720p/1080p шумит из-за прогрева и состояния GPU — это не
устойчивая зависимость скорости от разрешения. Peak PyTorch allocated GPU
memory около 84–88 MiB; CUDA context, память других приложений и CPU tensors
сюда не входят. Файл FP16 весов приблизительно 1,03 MiB. Скорость слабого CPU/GPU
нужно измерять отдельно; обещания real-time на любом оборудовании нет.
Полные записи: `benchmark_cpu.json`, `benchmark_gpu.json`.

CUDA overfit smoke: 4 синтетических fixtures, 200 шагов, LR 3e-4, BF16.
Alpha MAE 0,508 → 0,024; holes MAE 0,495 → 0,005; despill RGB MAE 0,105 → 0,031.
Заняло около 22 секунд; peak allocated около 479 MiB при 4×192².
Это только проверка обучаемости, **не оценка обобщения и не готовая модель**.
Полный результат: `smoke_gpu.json`. Полная тренировка на пользовательском датасете
в рамках переработки не запускалась.

Проверен и настоящий training forward/backward на двух изображениях
`ChromaKeyX_New`, native crops 512×512, BF16: около 791 MiB peak allocated,
примерно 56 мс на microbatch после прогрева. Подготовка двух источников на CPU
после оптимизации erosion занимает 0,24–0,25 с после прогрева. Это не время
полного optimizer step с накоплением, валидацией и загрузкой всех данных.
Запись: `native_training_smoke.json`.

Отдельно проверен запас VRAM для новой настройки: batch 8×512×512
(2,1 MP), BF16 forward/backward + AdamW — около 3184 MiB peak allocated,
83–84 мс после прогрева на случайных tensors. Поэтому стартовый бюджет V4
увеличен до 2 MP с accumulation 2. Запись: `training_capacity.json`.

CUDA integration-test запускает настоящий trainer, останавливает его посреди
накопления и продолжает. Веса совпали с непрерывным запуском (tolerance 1e-6);
проверены scheduler state и экспорт best. Для повторения включите переменную
`QDM_RUN_CUDA_INTEGRATION=1` перед запуском тестов. Для исключения сетевой проверки
обновления сторонней библиотеки можно установить `NO_ALBUMENTATIONS_UPDATE=1`.
